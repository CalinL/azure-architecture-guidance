Executive Summary

Microsoft provides multiple paths for building AI-powered Q&A agents over SharePoint content, ranging from zero-code to fully custom.

lightbulb Recommended Strategy

  1. Start with Option A (Foundry Agent + Foundry IQ + Teams) for fastest time-to-value
  2. Evolve to Option E (Hybrid) only when real user feedback demands a custom web app or advanced analytics

The core stack combines:

  • Microsoft Foundry Agent Service -- orchestrates the AI agent logic
  • Foundry IQ (Preview) -- managed knowledge layer that indexes SharePoint via Azure AI Search
  • Azure AI Search -- powers hybrid (keyword + vector) retrieval with ACL enforcement
  • Azure Bot Service / M365 Agents SDK -- bridges the agent to Teams and/or a custom web app
  • Azure Cosmos DB (optional) -- adds persistent conversation history and Q&A analytics
Important: Foundry IQ and the SharePoint tool in Foundry Agent Service are two different mechanisms with different capabilities and limitations.
report_problem

Problem Statement

search_off The Challenge

Organizations store critical knowledge across SharePoint. Employees struggle because:

  • Content is scattered across dozens of sites and libraries
  • Search returns documents, not answers
  • No institutional memory of previously answered questions
  • No contextual follow-up (each search is isolated)

flag Goal

  1. Answer natural-language questions grounded in SharePoint content
  2. Cite specific source documents
  3. Respect SharePoint permissions (security trimming)
  4. Track conversation history for follow-up questions
  5. Cache and surface popular Q&A pairs for analytics
  6. Accessible via Teams AND/OR a web application

Decision Tree: Which Option Is Right for You?

Important distinction: Foundry IQ (indexed knowledge base via Azure AI Search) and the SharePoint tool (live queries via Copilot Retrieval API) are different mechanisms.
architecture

Architecture Options

Option A -- Foundry Agent + Foundry IQ + Teams Recommended Start

Why Recommended as Starting Point

  • (+) Foundry IQ handles chunking, embedding, indexing, and retrieval
  • (+) SharePoint ACL enforcement via indexed ACLs or identity passthrough
  • (+) Publish to Teams via Foundry portal
  • (+) Can also serve a web app via Bot Service Direct Line
  • (+) Pay-as-you-go, no platform fee
  • (+) Built-in thread/conversation management
Caveats (April 2026): Published agents do NOT support citations in Teams. The SharePoint tool does NOT work in Teams-published agents; use Foundry IQ indexed sources instead. Foundry Agent Service does not support per-request MCP headers; for per-user auth, consider Azure OpenAI Responses API.

Key Components

ComponentPurpose
Foundry Agent ServiceAgent runtime & orchestration
Foundry IQ Knowledge BaseMulti-source indexed retrieval over SharePoint
Azure AI SearchIndex storage, hybrid search, ACL enforcement
Azure OpenAI (GPT-4o)LLM for response generation
Azure Bot ServiceChannel bridge (Teams + Web)
M365 Agents SDKTeams-native bot framework
Cosmos DB (optional)Persistent history & Q&A analytics
Entra IDAuthentication & identity passthrough

Option B -- Copilot Studio (Low-Code)

Pros

  • (+) No code required -- drag-and-drop
  • (+) Native SharePoint grounding with generative answers
  • (+) Built-in Teams and web widget deployment
  • (+) ~$200/month per tenant
  • (+) Built-in conversation analytics

Cons

  • (-) Limited customization
  • (-) Less control over RAG pipeline and prompts
  • (-) Cannot build complex multi-agent workflows
  • (-) Dependent on Copilot Studio roadmap

Best for: Non-technical teams, departmental Q&A bots, rapid prototyping

Option C -- M365 Copilot Declarative Agent (Zero-Code)

Pros

  • (+) Zero custom code -- JSON manifest only
  • (+) Native permission enforcement
  • (+) Available across Teams, Outlook, M365 Copilot
  • (+) No Azure infrastructure to manage

Cons

  • (-) Requires M365 Copilot license for ALL users (~$30/user/month)
  • (-) Least customizable option
  • (-) Cannot add custom backends, analytics, or caching
  • (-) Not interoperable with Foundry IQ knowledge sources

Best for: Organizations already licensing M365 Copilot for all users

Option D -- Custom Web App with RAG Pipeline

Pros

  • (+) Full control over UI/UX and agent behavior
  • (+) Build Q&A caching and analytics
  • (+) No M365 Copilot license required
  • (+) Suitable for external-facing scenarios
  • (+) Multi-cloud portability with Semantic Kernel

Cons

  • (-) Must build and maintain RAG pipeline
  • (-) Must implement SharePoint ACL enforcement manually
  • (-) Higher development and maintenance cost
  • (-) No out-of-box Teams integration

Alternative orchestrators: Semantic Kernel (open-source, runs anywhere) or LangChain can replace Foundry Agent Service for teams wanting cloud portability.

Best for: Teams needing full control or multi-cloud portability

Option E -- Hybrid: Foundry Backend + Custom Web Frontend

Why Consider This

  • (+) Best of both worlds -- Foundry IQ handles SP retrieval, custom backend adds features
  • (+) Full control over the web experience
  • (+) Q&A caching: store Q&A pairs, surface popular questions
  • (+) Teams AND rich web app simultaneously
  • (+) Full conversation history customization
Important: Only pursue this when Option A has been validated with real users and feedback shows need for custom UI or analytics. Do NOT start here.

Hosting choices: Azure Functions (event-driven, lowest cost) | App Service (always-on, built-in auth) | Container Apps (multi-service orchestration)

Deep Dive: Foundry IQ vs SharePoint Tool

Critical: These are two different mechanisms for accessing SharePoint from Foundry agents. Choosing the wrong one leads to broken architectures.

psychology Foundry IQ (Indexed)

  • Uses Azure AI Search to crawl, chunk, embed, and index SP content
  • Hybrid search (keyword + vector)
  • ACLs synced via index metadata
  • Pre-indexed -- fast but with indexing lag
  • Works with Teams-published agents
  • Exposes knowledge_base_retrieve MCP tool

bolt SharePoint Tool (Live)

  • Queries SP in real-time via Copilot Retrieval API
  • No pre-indexing -- always latest content
  • Permissions enforced natively by SP (OBO)
  • Requires M365 Copilot license or $0.10/call
  • Does NOT work in Teams-published agents
  • Best for dev/playground scenarios

Which to Use?

ScenarioUse This
Agent published to TeamsFoundry IQ (indexed) -- SharePoint tool does NOT work
Need real-time data freshnessSharePoint tool -- no indexing lag
Large-scale retrieval (100K+ docs)Foundry IQ -- pre-indexed for speed
No M365 Copilot licensesFoundry IQ (indexed) -- only Azure AI Search costs
Per-user permissions requiredBoth support this, different mechanisms

Deep Dive: AI in SharePoint

The AI in SharePoint feature (previously "SharePoint Knowledge Agent") makes your content AI-ready: Preview

label Key Capabilities

  • Auto-tagging -- classifies documents, extracts metadata (dates, names, contract numbers)
  • Content hygiene -- detects stale pages, broken links, duplicates
  • Natural language automation -- auto-creates workflows from plain English
  • Role-based actions -- adapts suggestions by role

tips_and_updates Why It Matters

A Foundry IQ + Foundry Agent solution is only as good as the SharePoint content it retrieves. AI in SharePoint ensures:

  • Documents properly tagged -> better retrieval relevance
  • Stale content flagged -> fewer inaccurate answers
  • Metadata consistent -> improved filtering precision

Recommendation: Enable alongside your Foundry solution.

Q&A Caching & Analytics Design

  1. Store Q&A pairs with citations and feedback ratings
  2. Popular questions surfacing -- aggregate frequently asked questions
  3. Feedback integration -- thumbs up/down drives prompt refinement
  4. Q&A cache -- high-confidence cached answers reduce model calls
  5. Content gap analytics -- track unanswerable questions

dns Partition Strategy

  • Partition key: userId (per-user) or conversationId (shared bots)
  • Indexes: vector index on embeddings for semantic search
  • TTL: Short-term context (24h), Long-term Q&A pairs (indefinite)

vpn_key Key Requirement: OBO (On-Behalf-Of) Flow

For SharePoint content retrieval to respect per-user permissions, the agent must use identity passthrough (not app-only tokens). This ensures:

  • Each user's query is executed under their identity
  • SharePoint ACLs are enforced in real-time
  • No data leakage between users with different permission levels

Anti-Patterns: What NOT to Do

  • warningDo NOT start with Option E (Hybrid) if Option A suffices -- validate with real users first, then evolve
  • warningDo NOT add Cosmos DB unless you have specific needs beyond Foundry's built-in thread management
  • warningDo NOT call Q&A caching "AI learning" -- the model does not fine-tune or adapt from past conversations
  • warningDo NOT use the SharePoint tool if publishing to Teams -- it won't work; use Foundry IQ indexed sources
  • warningDo NOT use Bot Framework v4 for new projects -- it's archived; use M365 Agents SDK
  • warningDo NOT assume "fully managed" means zero configuration -- you still manage Azure AI Search, OpenAI quotas, Entra ID, and Bot Service
  • warningDo NOT skip security testing -- test prompt injection defenses, verify ACL enforcement per user, validate OBO token handling
  • warningDo NOT ignore content quality -- enable AI in SharePoint to clean up stale/broken content before indexing

Implementation Roadmap

Phase 1 Foundation & Validation (1-2 weeks PoC, 4-8 weeks production)

Set up Foundry project + Azure AI Search (Free tier). Connect SharePoint as Foundry IQ indexed knowledge source. Create basic agent with system prompt + knowledge_base_retrieve MCP tool. Test in Foundry playground; validate ACL enforcement. Publish to Teams; test with pilot users (5-10). Collect initial feedback on answer quality.

Phase 2 Feedback-Driven Enhancement

Based on pilot feedback, decide: Teams-only (stay Option A) or custom web (evolve to Option E). If needed: add Cosmos DB for conversation persistence and Q&A caching. If needed: build custom web frontend (React/Blazor). Enable AI in SharePoint for content hygiene.

Phase 3 Scale & Optimize (if Option E)

Build Q&A caching engine. Add admin dashboard: usage analytics, content gaps, feedback review. Implement prompt engineering refinements. Scale Azure AI Search tier. Set up Azure Monitor + Application Insights. Implement rate limiting and circuit breakers.
